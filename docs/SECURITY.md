# LocalDock — نموذج الأمان

## الفلسفة

> **Safe by Default** — المشاركة الجديدة Read Only وبلا ضيوف، وكل توسيع صلاحية هو قرار صريح من المالك.

المنتج LAN-first: لا يُعرض أي شيء على الإنترنت افتراضيًا، ولا يعتمد على أي خدمة خارجية. الأمان مصمم ليكون **غير مرئي** في التجربة الأساسية (§17 من المواصفات): المستخدم يرى "🟢 Local Network Only — Trusted Devices: 3" فقط.

## الهويات الثلاث

| الهوية | كيف تُثبت | ماذا تستطيع |
|---|---|---|
| **Owner** | ترويسة `X-LocalDock-Owner` بمفتاح 48-hex يولَّد عند أول تشغيل | كل شيء: إدارة المشاركات والأجهزة والإعدادات |
| **Device** | ترويسة `X-LocalDock-Device` برمز 64-hex من عملية الاقتران | الوصول للمشاركات المسموح لها به حسب صلاحيتها |
| **Guest** | لا شيء — زائر بلا اقتران | فقط المشاركات التي فعّال المالك `guestEnabled` لها، وبمستوى صلاحية المشاركة |

### حدود Owner

- `settings.allowRemoteOwner = false` (افتراضي في غلاف سطح المكتب) ⇒ لوحة التحكم تُخدم من جهاز السيرفر فقط (loopback/شبكة خاصة) حتى لو تسرب المفتاح.
- المفتاح لا يغادر الخادم إلا عبر `/api/bootstrap` الذي يُقيَّد بنفس القاعدة.

### الاقتران الآمن

1. المالك يضغط "Add Device" → كود 6 حروف من أبجدية بلا أحرف ملتبسة (لا 0/O، 1/I/L).
2. الكود **أحادي الاستخدام**، ينتهي بعد **5 دقائق**، ويُستهلك فور المطالبة (مُختبر: إعادة الاستخدام → 401).
3. المطالبة تُصدر `deviceToken` (256-bit) يُخزَّن على الخادم **hashed بـ SHA-256 فقط** — تسريب قاعدة البيانات لا يكفي لانتحال جهاز.
4. QR يحمل الرابط مع الكود — الـ QR وسيلة نقل الكود، وليس هوية بحد ذاته؛ حتى لو صُوِّر لاحقًا فقد انتهت صلاحيته واستُهلك.
5. إلغاء الجهاز فوري ومحلي (حذف السجل = الرمز ميت).

### مصفوفة صلاحيات المشاركة

| الإجراء | Read Only | Read & Write |
|---|---|---|
| تصفح/بحث | ✓ | ✓ |
| تنزيل/معاينة | ✓ | ✓ |
| رفع/إنشاء مجلد | ✗ | ✓ |
| إعادة تسمية | ✗ | ✓ |
| حذف | ✗ | ✓ |

تُطبَّق عبر `canAccessShare()` على **كل** مسار ملفات، مع قائمة أجهزة لكل مشاركة (`all` أو قائمة صريحة) — الجهاز غير المسموح له يرى المشاركة وكأنها غير موجودة (403/404).

## الدفاعات التقنية (كلها مُختبرة)

### Path Traversal — أولوية قصوى
- `resolveSafe()` المركزي: يرفض `..`، المسارات المطلقة، مسارات الأقراص `C:`، null bytes، وBackslashes كفواصل، ثم يتحقق أن المسار المحلّل يبدأ فعليًا بالجذر (دفاع عمق ثانٍ بعد التطبيع).
- `resolveSafeInside()` يمنع الوصول للجذر نفسه للعناصر (rename/delete/download).
- أسماء الملفات عبر `sanitizeName()`: رفض null bytes كليًا، طيّ نقاط `..`، رفض dotfiles، أسماء Windows المحجوزة (CON, NUL...)، المحارف الممنوعة، والطول المفرط.
- مُغطى بـ 12 اختبار وحدة + 5 اختبارات تكامل (browse/download/upload/folder/site).

### سلامة البيانات
- SHA-256 إلزامي على الخادم عند إتمام كل رفع (بثّ، لا ذاكرة)، ومطابقة اختيارية من العميل.
- تحقق الحجم مقابل المُعلن قبل الاعتماد.
- ملف موجود مسبقًا → تعارض مُدار (`name (1).ext` أو overwrite صريح) — لا صمت ولا كتابة فوق غير مقصودة.
- تعديلات الميتاداتا عبر `withLock` (تسلسل عمليات) + كتابة ذرّية (tmp+rename) — انقطاع كهرباء لا يُفسد السجلات.

### حماية الـ API
- كل مسارات الإدارة خلف `requireOwner` (401 بدون مفتاح — مُختبر).
- كل مسارات الملفات خلف `shareGuard` مع تسجيل محاولات الرفض في سجل النشاط (`security.denied`).
- التحقق من صحة `uploadId` قبل لمس القرص؛ فهرس chunk خارج النطاق → 400/404؛ جلسة غير موجودة → 404 (مُختبر).
- حد أقصى لحجم chunk (16MB) وحدهم أدنى (64KB) لمنع الاستنزاف؛ body limits عبر المنصة.
- الرؤوس: `X-Content-Type-Options: nosniff` على كل ملف، `Content-Disposition: attachment` للتنزيل، `Cache-Control: no-store`.

### استضافة المواقع
- قراءة فقط، احتواء كامل داخل مجلد الموقع، لا directory listing، MIME مقيد، 404 لكل شيء آخر.
- محاولة traversal عبر `/sites/x/../../` → محجوبة (مُختبر).

## ما هو خارج النطاق عمدًا (v1)
- **HTTPS/حماية من sniffing داخل LAN**: حماية أصلية تتطلب شهادات CA خاصة وتُكسر تجربة "افتح الرابط فورًا". نموذج التهديد المحلي: أعضاء شبكتك المنزلية/المكتبية. غلاف سطح المكتب يضيف HTTPS اختياريًا بشهادة موقعة محليًا (خارطة طريق، البنية جاهزة).
- **تشفير التخزين**: الملفات تبقى كما هي على القرص — LocalDock طبقة مشاركة، لا طبقة تخزين مشفر.
- **Rate limiting صارم**: الخادم LAN-only بطبيعته؛ الحدود الصلبة على chunk sizes وعمق البحث تغطي استنزاف الموارد العرضي.

```bash
bun test tests/unit                    # 12+ حالة traversal/تطهير
bun tests/smoke.mjs http://localhost:3000
```

قسم الأمان في smoke tests يغطي: رفض بلا مفتاح، رفض بمفتاح خاطئ، guest محظور/مسموح، traversal في browse وdownload وsites، أسماء عدوانية (`../evil`، null byte)، كود اقتران مستهلك، رمز ملغى، وحجم chunk خاطئ.
